# X Shortcut Plus 1.1.1-beta.1

Fixes the account shortcut stopping after it opened the account panel in 1.1.0-beta.1.

The old adapter required `AccountSwitcher_LoggedInAccountList` and a row for the current account. The user supplied a live `UserCell` button with `aria-label="Switch to @projectarisu"` and a matching `UserAvatar-Container-projectarisu` marker. The revised adapter recognizes that button without either assumption. It selects the first displayed alternative when there is no current-account row. The previous named-list adapter remains supported.

The shortcut remains `Ctrl+Alt+a`. Return-URL and Home-feed restoration are unchanged. All other changes from [1.1.0-beta.1](1.1.0-beta.1.md) remain included.

Chrome’s numeric version is `1.1.1`. The display version is `1.1.1-beta.1`.

## Verification

- The minimized captured-button regression failed before the fix and passes afterward.
- `npm test` passes 57 checks, including dialog handling, unrelated user cells, mismatched identities, and displayed alternative order.
- Visible Chromium fixture checks passed with the captured button structure and no named list container or current-account row. A real `Ctrl+Alt+a` selected the alternative account. The fixture reloaded through Home, then restored the original URL, query, and fragment.
- `npm run package` passed bundle syntax, required-file, ZIP integrity, and checksum checks.

These checks use the supplied markup and a simulated account transition. A full live account switch remains unverified. No store upload occurred.

## Update

1. Extract `release/x-shortcut-plus-1.1.1-beta.1.zip` into the folder used for the unpacked extension.
2. Reload the extension in `chrome://extensions`.
3. Reload the X tab.
4. Test `Ctrl+Alt+a` from the page you want to retain.
