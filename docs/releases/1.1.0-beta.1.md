# X Shortcut Plus 1.1.0-beta.1

This candidate implements changes for all five open GitHub issues. Authenticated X validation remains pending. The issues remain open until that check confirms the behavior.

Chrome’s numeric extension version is `1.1.0`. The display version is `1.1.0-beta.1`.

## Changes

- [#1](https://github.com/kriss-spy/x-shortcut-plus/issues/1): Removed the repeated browser warning from Ctrl+Alt defaults. Settings retain one general notice. Native-key conflicts, likely browser shortcuts, and duplicate bindings still show warnings.
- [#2](https://github.com/kriss-spy/x-shortcut-plus/issues/2): Added configurable `Ctrl+Alt+3` through `Ctrl+Alt+9` bindings for displayed feed positions. The first two feeds retain `Ctrl+Alt+1` and `Ctrl+Alt+2`. Position bindings follow reordering and work without list IDs. Individual list bindings still follow list identity.
- [#3](https://github.com/kriss-spy/x-shortcut-plus/issues/3): Added `Ctrl+Alt+a` to cycle to the next signed-in account through X’s account menu. It restores the current tab’s URL, query, and fragment after X returns to Home. On Home, it also attempts to restore the selected feed. Exact scroll position is not preserved.
- [#4](https://github.com/kriss-spy/x-shortcut-plus/issues/4): Settings now recommend X’s native `.` for loading posts. Top and new posts remains optional and has no default binding. Explicitly saved bindings remain unchanged.
- [#5](https://github.com/kriss-spy/x-shortcut-plus/issues/5): Added `Ctrl+Alt+u` to open the focused post’s author. On a post detail page, it can use the main post without focus. It excludes quoted authors and preserves `g` sequences.

## Install

1. Run `npm ci`.
2. Run `npm test`.
3. Run `npm run package`.
4. Extract `release/x-shortcut-plus-1.1.0-beta.1.zip` into a permanent folder.
5. Load that folder through `chrome://extensions` with Developer mode enabled.
6. If updating an unpacked installation, reload the extension and existing X tabs.

Saved overrides and explicit clears take precedence over defaults. Newly added defaults can conflict with a custom binding. Settings flag duplicates and disable both affected actions until you change one.

## Verification and limits

`npm test` passes 52 automated checks. `npm run package` checks bundle syntax, required manifest files, ZIP integrity, and the package checksum.

A visible Chromium profile loaded the unpacked extension against locally fulfilled X fixtures. Real keyboard checks passed for feed positions after reordering, the author action, native period, typing protection, and account switching across a full document reload. The return URL retained its query and fragment. Settings had no default warning rows, saved a new action binding across reload, and fit a 390-pixel viewport. No page JavaScript errors occurred.

These fixtures verify extension behavior against the supplied DOM forms. They do not confirm current authenticated X markup. In particular, the account menu’s test IDs and post-focus behavior require live validation. Unknown controls cause the action to stop. Account return records expire after 30 seconds. Private or unavailable destinations remain subject to the target account’s X permissions.

No Chrome Web Store upload or review submission occurred.
